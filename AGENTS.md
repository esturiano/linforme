# AGENTS.md

## Цель проекта
Разрабатывать модульный, простой и поддерживаемый код. Соблюдать архитектурную и кодовую политику проекта. Любые изменения вносить в ответственные за это места.

## Стиль мышления
- **Максимально сокращай размышления.** Не расписывай длинные цепочки рассуждений — сразу формулируй вывод и действие.
- **Не допускай закольцовывания рассуждений.** Если рассуждение вернулось к уже пройденной точке — остановись, зафиксируй тупик и выбери другой путь.
- **Решения не должны быть поспешными.** Сначала пойми задачу и контекст, затем предлагай решение.
- **Не повторяй попытки без изменения подхода.** Если способ не работает — меняй способ, а не повторяй.

## Архитектурная и кодовая политика
- Строго придерживайся архитектурной и кодовой политики проекта. Если политика неясна — сначала уточни, потом действуй.
- Стремись к **модульному решению**:
  - каждый модуль — отдельный каталог;
  - у модуля — свой локальный `CMakeLists.txt`;
  - файлы модуля не разбрасываются по чужим каталогам.
- Изменения вноси **только в ответственные за это места** (тот модуль/файл, который отвечает за функциональность).
- Не дублируй логику между модулями: общее выноси в отдельный модуль.

## Точки входа
- **Минимизируй размеры `main.qml`, `main.cpp` и аналогичных точек входа.** В них — только инициализация, сборка и запуск.
- Весь содержательный код размещай в файлах соответствующих модулей.

## Качество кода
- Код должен быть **максимально простым** (не заумным). Предпочитай очевидные решения хитрым.
- Избегай преждевременных абстракций и «на всякий случай» обобщений.
- Имена — понятные, отражают назначение.
- Не оставляй мёртвый код, закомментированные блоки, отладочные заглушки.

## Смена подхода
- Если способ решения задачи отменён и выбран другой — **старый код должен быть полностью удалён**, а не оставлен «на память» после неудачной попытки.
- Не держи параллельно две реализации одной задачи.

## CMake
- Каждый модуль описывается своим `CMakeLists.txt` в своём каталоге.
- Корневой `CMakeLists.txt` только подключает модули (`add_subdirectory`) и задаёт общие настройки проекта.
- Зависимости между модулями указывай явно (`target_link_libraries` и т.п.).

## Процесс работы
1. Прочитай задачу и определи ответственный модуль.
2. Проверь политику проекта по этому участку.
3. Внеси минимальные изменения в ответственных местах.
4. Если подход меняется — удали старый код.
5. Проверь, что точки входа (`main.*`) не разрослись.
6. Убедись, что сборка проходит и модули собираются через свои локальные `CMakeLists.txt`.

## Архитектурный вход
- Исходного кода в репозитории нет: только `archforme.sh`, `debforme.sh`, `AGENTS.md`, `LICENSE` и `.vscode/sftp.json`. Модулей, каталогов исходников и артефактов сборки не существует.
- `archforme.sh` — обустройство свежеустановленной Arch-based системы: `pacman`, `reflector`, сборка `yay` из AUR (`git clone` + `makepkg -sir`), далее пакеты через `yay -S`.
- `debforme.sh` — обустройство свежеустановленной Debian-based системы: `apt`, `dpkg`, `opam`, сторонние `.deb` и архивы.
- Точки входа — сами скрипты, исполняются сверху вниз; «модулей» нет, общий каркас — свой блок `while true; read yn; case` на каждое действие.
- Единственная сборка из исходников — `glabels-qt` внутри `debforme.sh`; остальное — установка готовых пакетов и распаковка чужих архивов.
- Раздел «CMake» выше — общая политика шаблона: своего CMake-проекта в этом репозитории нет.

## Команды сборки и проверки
- Бита выполнения у скриптов нет — запускай явно: `bash archforme.sh`, `bash debforme.sh`.
- Запускать из `$HOME`: скрипты используют относительные `cd` и пишут в `~` (`~/.esturiano@yandex`, `~/.drive@*`, `~/.zshrc`, `~/.oh-my-zsh`).
- Нужны `sudo` и интерактивные ответы `y`/`n`. Скрипты ставят пакеты, переписывают зеркала, включают `libvirtd`/`cups`, кладут файлы в `/usr/share/sounds` и `/usr/local/bin`, а в конце предлагают удалить себя (`rm -f archforme.sh`).
- Проверка без выполнения: `bash -n archforme.sh` и `bash -n debforme.sh` (обе проходят). `shellcheck` в системе не установлен.
- `debforme.sh` ставит инструменты через `apt`: `curl`, `wget`, `unzip`, `cmake`, `build-essential`, `pkg-config`, `opam`/`ocaml`, `fuse` и Qt-пакеты (`libqt5svg5-dev`, `qt5-default`, `qttools5-dev`).
- Сборка `glabels-qt`: `wget` архива `glabels-3.99-master561.tar.gz` с GitHub, `tar -xf`, затем в распакованном каталоге `mkdir build && cmake .. && make && sudo make install`.
- Содержимое (архивы звуков, `oracle-java8-jdk_8u151_amd64.deb`, `firefox-51.0.1.zip`, `master-pdf-editor-4.3.89`) качается `curl` по file id из Google Drive; контрольные суммы не проверяются.
- `CMakePresets.json` и тестов в репозитории нет — `ctest` не используется.
